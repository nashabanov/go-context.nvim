*go-context.txt*  Per-workspace Go build tags for Neovim

==============================================================================
SETUP                                                        *go-context*
                                                             *go-context-setup*
Requires Neovim 0.10 or later. Enable commands and tag suggestions: >lua

    require("go-context").setup()
<
To apply saved tags when gopls starts, add this field to your existing gopls
configuration: >lua

    before_init = require("go-context").before_init,
<
The plugin does not install or start gopls. Context changes update running
gopls clients with a matching workspace root.

==============================================================================
COMMANDS                                                     *go-context-commands*

:GoContext                                                   *:GoContext*
        Open a compact floating input with the current workspace tags.
        Enter saves; Esc cancels. Separate tags with commas or spaces.
        Submit an empty value to save an empty tag list. Cancel to leave the
        context unchanged.

:GoContext {tags}
        Replace the workspace tags with a comma- or space-separated list.
        Duplicate tags are removed while preserving order. Examples: >vim

            :GoContext integration,smoke
            :GoContext integration smoke
<
:GoContext!                                                  *:GoContext!*
:GoContextClear                                              *:GoContextClear*
        Clear the workspace tags, remove the saved context, and remove the
        -tags build flag from matching gopls clients. Other flags are preserved.

Commands use the current buffer's workspace. Its root is resolved from an
attached gopls client, or from a parent directory containing go.work or go.mod.
Contexts persist outside the repository under:

    stdpath("state")/go_context.nvim/

==============================================================================
TAG SUGGESTIONS                                               *go-context-suggestions*

Entering a *.go buffer checks //go:build directives before the package
declaration. A compact floating window lists new custom tags and offers
"Add tags" or "Ignore for this session". Use j/k, arrow keys, or Tab to
choose an action; Enter confirms and Esc cancels. Colors follow your theme.

Accepted tags are appended to the workspace context and saved. Declining or
dismissing a prompt suppresses those tags in that workspace for the rest of
the Neovim session. Other workspaces are unaffected.

GOOS/GOARCH values, unix, cgo, gc, gccgo, ignore, go1.<number> release tags,
and directly negated tags such as !enterprise are excluded. Boolean expressions
are not fully parsed: postgres || sqlite suggests both tags.

Only the current buffer is inspected. Legacy // +build directives and filename
constraints are not considered. Tags are never removed automatically.

==============================================================================
LUA API                                                      *go-context-api*

    local gc = require("go-context")
    gc.root(opts)           -> root or nil, error
    gc.get(opts)            -> context or nil, error
    gc.tags(opts)           -> copied tag list, or {} on missing context/error
    gc.set(context, opts)   -> normalized context; raises on failure
    gc.clear(opts)          -> { tags = {} }; raises on failure
    gc.before_init(params, config)
    gc.setup()

opts is optional: { root = "/path/to/project", bufnr = 12 }. Explicit root
wins over bufnr; otherwise the current buffer is used. Root must be a nonempty
path. Relative paths use the current working directory; roots become absolute
and existing paths resolve through symlinks. The fallback uses the nearest
go.work or go.mod. Distinct attached gopls roots return an ambiguity error.

Context is { tags = { "integration", "smoke" } }. Tags must be a list of
strings containing letters, digits, underscores or dots. Order is preserved;
duplicates are removed. Returned contexts/lists do not alias persisted state.
get() returns nil without error when no saved context exists. Use get() rather
than tags() to distinguish errors from an empty context.

setup() accepts no options. Repeated calls replace commands/autocmds without
resetting the session's declined tags. before_init can be composed with an
existing callback; call it after your configuration changes.

==============================================================================
EVENT                                                        *go-context-event*

Successful set()/clear() triggers User GoContextChanged with event.data:

    { root = normalized_root, context = { tags = { ... } } }

The event context is copied. It fires after saving/deleting state and sending
client configuration updates. Server reloading is asynchronous; the event does
not guarantee that gopls has finished applying the new configuration.

==============================================================================
STORAGE AND ERRORS                                           *go-context-storage*

Records use version-1 JSON at stdpath("state")/go_context.nvim/<root hash>.json.
Saving uses a temporary file followed by rename. Corrupt/unreadable state raises
an error in the storage layer; get() returns nil, error. Loading never repairs
or overwrites a corrupt record. Commands notify errors. before_init warns and
leaves configuration unchanged when loading fails.

Clear deletes state before updating clients; deletion failure leaves their
settings unchanged. Persistence and client updates are not a transaction: an
LSP notification failure may occur after the saved record changed. Concurrent
Neovim sessions use the last successfully saved context.

Existing -tags options are replaced; unrelated buildFlags are preserved.
Clearing removes -tags from matching clients. With no saved context, before_init
leaves manually configured flags unchanged. A saved empty list removes tags.
Client matching uses config.root_dir, not individual workspace_folders. Separate
clients are required for independent contexts across folders in one LSP session.

The plugin does not modify Go test, debugger, or linter commands. Detection
extracts identifiers rather than parsing Go syntax; parenthesized negations,
block comments and malformed expressions are not interpreted semantically.
